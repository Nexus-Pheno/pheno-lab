# Private chemical definitions

Pheno Chemicals is a separate, default-deny chemistry workbench. An active ADMIN/MANAGER with an explicit `chemicalAccess` grant, approved membership, active organization and no setup/testing/shared-device restriction can read and edit it. There is no implicit administrator or stewardship bypass. The approved initial two recipients are resolved and checked by the operator; the application exposes no permission-grant action.

Names/categories remain in the shared Material catalogue, available to existing employee pickers. Public material DTOs use the explicit `publicMaterialSelect` allowlist and omit SMILES/private evidence. Library forms, suggestions, experiment payloads and intake reads cannot disclose the dedicated private fields. Public edits preserve existing SMILES; nonempty private-chemistry changes must use this portal. Legacy definitions are retained without backfill or automatic validation. The portal lists only explicitly registered chemistry definitions, independently of shared-library membership and category. The legacy field name MaterialChemistry.inSamRegistry now represents portal membership across supported categories; no migration or catalogue backfill is needed. SAM, ADDITIVE, SOLVENT and organization-defined categories use the same shared category definitions. A new row matching exactly one active, unregistered library material reuses its Material ID, preserves its name, supplier/lot/properties/notes/process/experiment links, and synchronizes the explicitly submitted category and SMILES. Already registered names require editing their existing row; ambiguous active names or archived-only matches receive specific errors rather than an arbitrary merge. Case-insensitive same-name retries retain one identity. The private analysis export still includes the historical catalogue, preserving available evidence for longitudinal analysis.

RDKit 2026.9.1 runs locally in the existing Node process: no LLM/provider calls, tokens, external chemistry uploads, new service or new environment setting. It validates notation, preserves charged/stereochemical graphs, canonicalizes SMILES and generates an SVG. Notation validity does not establish supplied-substance identity or purity. Oversized, malformed, wildcard-placeholder and markup inputs are rejected.

SMILES remains authoritative on Material. MaterialChemistry holds canonical notation, version, request ID, local-engine provenance and private image integrity/reference metadata. SVG bytes use the existing COS adapter in an organization-specific chemical namespace. Saving a row is audited and transactional; retries use the same request ID, stale edits conflict, and failed transactions remove only a newly uploaded unreferenced object. Successful replaced images are retained; no automatic historical deletion occurs. Direct structure reads check fresh authorization, scope, current-input digest and stored hash/bytes, and return no-store/nosniff/sandboxed SVG. Generic attachment readers always deny the namespace.

The private, audited `/api/chemicals/analysis` export is available only to the same chemistry maintainers. General data/analysis exports remain public-catalogue projections. Private definitions must not appear in reports distributed to managers without chemistry access or in public research requests. The scheduled analysis workflow can use authorized definitions internally and share appropriately scoped findings without raw/canonical SMILES or molecular images.

Approved initial operator provisioning reads reviewed JSON through stdin to `NODE_OPTIONS=--conditions=react-server pnpm exec tsx scripts/grant-chemical-access.ts`, using the existing runtime environment. Input: organizationId, exactly two distinct approved recipientIds, non-secret authorizationReference. It validates current identities/account state, refuses unexpected other grants, and records grants/audits atomically. Retry produces no additional grants/audits. No scientific records or existing source definitions are changed by provisioning.

An explicitly authorized portal-ready notice can be sent using `scripts/announce-chemical-portal.ts` under the same operator conditions. Input: organizationId, senderUserId, recipientUserId, authorizationReference. Both identities must retain current private chemistry access in that organization. Exactly one bilingual `chemicals_ready` in-app notice links to `/chemicals`, with an audit in the same transaction; replay does not duplicate it. This operation does not grant permission, include chemistry data or send a group message. Opening the real notification panel marks notices read, so operator verification should inspect unread state without opening the recipient's panel.

Before release: guarded PostgreSQL integration/drift, affected browser cases, full repository verify, EN/ZH desktop/mobile visual review and artifact checks. Deployment and rollback follow the existing deployment manual; earlier code lacks these privacy restrictions.

Bulk upload is available at `/chemicals/bulk`, with the same fresh private chemistry gate for its page, template, validation, import and source-workbook download. The protected static Excel template has only Molecule name/SMILES on SAM Materials; bilingual instructions/public 2PACz example are on a separate non-imported sheet. Only plain-text `.xlsx`, at most 100 nonempty rows/2MB, is accepted. ZIP expansion, worksheet dimensions, macros, external links/entities and formulas are bounded/rejected before parsing. Preview validates all graphs and reports exact Excel row numbers without writes. An explicit confirmation binds the exact file digest and batch UUID.

A category chosen on the upload page applies to the whole two-column file. Preview marks existing-library links. Already registered, ambiguous or archived-only names block import, while unique unregistered library matches are linked without duplication. Replay binds file SHA and category; older batches retain SAM defaults. Original XLSX and every locally generated SVG use new private COS keys and complete read-back/hash verification before a bounded atomic database transaction. Fresh scoped grants and current duplicate names are checked again. ChemicalImportBatch preserves the original file and source-row/material mapping; imported evidence retains its batch relation across later edits. Replay is idempotent, differing input cannot reuse a batch ID, and failed/losing concurrent attempts clean only their own unreferenced objects. Public and private material writers share the organization advisory lock so concurrent creation/renaming cannot evade the import's conflict check. No existing scientific records are updated, no production import is performed during release QA, and general file readers still deny this entire namespace. See the existing data-import rules for reconciliation and approved detach/archive steps.

An explicitly approved portal reset uses `scripts/initialize-sam-registry.ts` under the existing operator conditions. It accepts organizationId, actorUserId, referenceMaterialId, expectedDigest, expectedStructureSha256 and authorizationReference through bounded stdin. It verifies current maintainership, organization, SAM category, saved image integrity and source digest before atomically replacing portal membership with the reviewed reference and recording a SYSTEM audit. It never deletes/archives materials, changes source SMILES, rewrites experiment references or removes images. Replay is idempotent; a concurrent edit requires new review. Inline structures are visible within each row at all widths; the larger inspector remains optional.
