# Chemical registration, library linking and shared categories

Michael requested allowing an existing library name absent from Pheno Chemicals to be registered without duplicating its material, removing the per-row atom selector, and adding SAM/Additives/Solvents plus custom categories synchronized with the shared library. Read-only live inspection found exactly one active 4PACz SAM with no chemistry evidence, matching the reported conflict scenario.

Single saves and Excel imports now reuse the unique active unregistered Material ID, preserve its name and other metadata/references, and synchronize explicitly submitted category/SMILES. Already registered names remain protected; ambiguous or archived-only names require review rather than arbitrary selection/reactivation. Same-name matching and retries are case-insensitive. Existing row edits retain version/digest protection and same-transaction audit; failures roll back existing rows as well as new ones. Bulk imports use verified private COS originals/graphs, atomic mixed link/create transactions, immutable source-row manifests and category-bound retries. Public writers share the same lock; a concurrent unique library creation is linked rather than duplicated.

The existing membership field name inSamRegistry is retained as registry membership across categories; no schema migration, backfill, reset or new grant is needed. Existing explicitly registered rows stay visible. The three category choices use existing SAM/ADDITIVE/SOLVENT codes; custom creation is private-authorized, organization-scoped, audited and shared with the library. Plural builtin aliases coalesce to those codes. Excel's two-column sheet remains compatible, with category chosen per file on the upload page. Template instructions and the bilingual Bruce guide were updated.

The atom button is removed. Row clicks/focus select the structure while inline images and the larger inspector remain. English/Chinese labels, existing Pheno workbench/tokens and responsive pane behavior are retained.
